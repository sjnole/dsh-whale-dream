## 对照依据
用户实机截图：`image(20261117-112309).png` 队列、`image(20261117-112319).png` 圆形入口、`image(20261117-112331).png` 胶囊；UI 依据：`鲸梦V1.3-深色设计总览.png`、`鲸梦V1.3-浅色设计总览.png`、`鲸梦V1.3-会话队列交互.png`。参考演示：`docs/whale-companion-V1.3.html`。此交付针对 **Win32 原生 GDI+ 渲染**，不是把设计图做成桌面贴图。

## 经过源码验证的根因及变更
1. **26 条均显示待处理（核心数据 Bug）**：`lib/client.js` 会将静止会话推送为 `status: 'idle'`，原 `lib/dream-host.js` 的 `cleanCompanionSnapshot()` 白名单却没有 `idle`，并把不认识的状态全部改为 `'waiting'`。结果：`已同步 26`、`运行中 0`、`待处理 26`，所有卡片被错误染成琥珀色。本次明确允许 `idle`，未知值降级为 `idle`。真实 Host HTTP 接口测试覆盖 26 idle、未知值及运行/确认/完成/空闲混合场景。
2. **圆形、胶囊外部的方形底色/半透明边框**：native 先把整个客户区涂为与玻璃主体不同的 `p.bg`，再画抗锯齿圆角，边缘会露出底色；`CreateRoundRectRgn` 使用了 w+1/h+1；DWM 又额外施加圆角和系统边框；Mini 即使没有运行中的任务也额外合并徽标区域。这是多个**独立**的轮廓来源。新版底色与主体色一致、Win32 region 以实际宽高创建、关闭 DWM 额外圆角及系统边框，仅在运行数量 >0 且窗口已经接近圆形时使用徽标区域。
3. **实体卡片颜色与 HTML 差距**：原绘制使用过强的状态色和白色混合（将 18–32% 状态色大面积灌入卡片底色，发灰发橙）。现在卡片主体保持深蓝玻璃，状态色作用于较细的轮廓、点缀及图标；无模型名显示 `DSH 会话`，无真实费用时省略费用占位横线，不再误导用户。
4. **展开有跳帧感**：原 Win32 UI 将 `SetTimer(...,32ms)` 与逐帧 `SetWindowPos`、`SetWindowRgn`、GDI+ 重绘绑定；这是约 31Hz 的离散推进，不等于浏览器中 270ms CSS 动画。新版时间驱动 240ms 展开、16ms 目标唤醒、高精度计时器只在过渡期间开启；跳过整数坐标不变的帧；避免重复构造相同尺寸/状态的裁剪区域；迷你态 DIB 按需分配，而非启动时预分配 492×660 大画布。
5. **静态运行辉光造成低帧率闪动**：节能档现在为静态边缘微光（无持续绘制）；均衡/顺滑仅在真实运行中增量计时，无任务立即停表；低动态也停表。队列仍用矢量底色绘制，并非 PNG 蒙皮。
6. **无法定位 Windows 实机卡顿的剩余来源**：添加过渡耗时诊断 `~/.dsh/whale-dream-companion/performance.json`（Windows 上为用户目录 `.dsh\\whale-dream-companion\\performance.json`），包含原生 GDI+ 回调耗时、慢帧间隔数与整次过渡耗时。**该文件只有在 Windows 实际运行并完成展开/收起后才有有效数据**；不会每帧写磁盘。

## Windows 验收建议
1. 完整退出 DSH 主进程及托盘进程后，用 `dsh-whale-dream-0.8.64.tgz` 安装，重启 DSH。
2. 将主题设为跟随 DSH，分别在深浅主题检查圆形、胶囊、队列三态的轮廓，不应额外出现灰色方框或双层边框。
3. 让多个历史会话处于非运行状态，确认 `运行中 0 / 待处理 0`；只有确实需确认、输入、排队的会话变黄。
4. 切换「节能/均衡/顺滑」，测试同一台 Windows 设备上打开和收起 10 次；发生卡顿时查看 `performance.json` 的 `slowFrameGaps / maxPaintMs / elapsedMs`，可以进一步判断是绘制超预算还是窗口合成层受限。该诊断记录的是回调与时间间隔，不等于显示器真实 VSync FPS。
5. 低动态模式应直接切换，不再播放形变动画；未能确认的行为应保留实机截图而非报告为已通过。
