# Whale Dream 0.8.3 验证记录

## 范围

本轮针对用户提出的不同配置电脑性能影响、卡顿、bug 和稳定性，保留 0.8.2 的 38 项美术、全幅尺寸与功能，优化渲染准备工作、绘制调度和资源生命周期。

`npm run check` 已完成：TypeScript 检查、生产构建、自包含预览与离线自检页导出成功；419 / 419 项测试通过，0 失败、0 跳过。完整测试耗时约 115.51 秒，输出保存在 `docs/test-results-0.8.3.txt`。

## 已复现并修复

- 0.8.2 的海洋接收 300 次相同尺寸通知会重设主画布 600 次；新版相同几何与 DPR 直接返回。
- 0.8.2 的非海洋场景隐藏时，50 次设置更新仍触发 50 帧绘制；新版延后到可见时绘制。
- 海洋主题更新的离屏底图工作一并延后到下一可见帧；减少动态和输入暂停恢复可见时仍补画当前帧。
- 减少动态首次准备 240 步后，时间实际为 `3.9999999999999907`，旧版再次准备静态帧会误判未完成并多前进约 4 秒。新版使用明确的一次性标志，主题和可见性变化保留静态世界时间。
- 植物缓存遗漏了花瓣高光色；相近颜色切换会命中不完整的旧键。新版以完整配色识别缓存，冷启动和切换后的画面保持一致。
- 0.8.2 销毁后，外部仍持有的 960×640 主画布保留 614,400 像素；新版主动将主画布及自有临时画布清零，并释放网格和字形缓存。
- 高 DPI 视口不再无上限按 2 倍宽高扩张背景缓冲。有效 DPR 受约 829 万物理像素预算约束，CSS 场景尺寸、点击坐标和对象数量保留。
- 字形缓存同时限制 6000 项与约 16 MiB 理论 RGBA 容量，避免大字格仅按数量限制时保留过多像素；逐项淘汰，静态预览保留成品。

## 专项验证

- 38 外观各重复切换、热重载、输入暂停、离屏/隐藏、减少动态、连续点击与大时钟跳跃。
- 实际两种引擎注入绘制成本，验证持续高负载降帧、低负载缓慢恢复，维持同一引擎、画布、用户帧率上限和世界进度。
- 边界测试覆盖高 DPI 像素预算、非法采样、自定义帧率、暂停间隙与单次冷启动抖动。
- 原生像素验证资源释放不会清除仍在使用的静态卡片；字形缓存逐项淘汰，所有临时测字画布及时释放。
- 星空调色板/几何缓存与 0.8.2 生产图逐字节比较，覆盖深浅色、DPR、连续动作与缓存淘汰。
- 樱花、花野、竹林、荷塘的深色 DPR 1、浅色 DPR 1、深色 DPR 2 共 12 个样例逐字节一致。蒲公英仅对绒球批量绘制，约 1.19–1.75% 画布像素存在微小抗锯齿差异，最大 alpha 差 10/255；对照图已审阅，轮廓、构图与数量保持。
- 旧暂停 resize 测试已校正为真正改变尺寸：相同通知不重绘，480×280 → 640×360 在输入暂停时补画一次，保持原世界、时间和暂停状态。

## 性能证据

完整数据、方法、对比、图表和电脑自检说明见 [PERFORMANCE-0.8.3.zh-CN.md](PERFORMANCE-0.8.3.zh-CN.md) 及 `qa/performance-0.8.3/`。所有 Native Canvas 计时在同一执行环境内顺序运行；不是 Windows DSH 实机 FPS，也不是不同 CPU/GPU 的跑分。

固定窗口和 DPR 的实际数据只能比较当前前后实现；理论 RGBA 缓冲不是进程内存/显存。注入耗时与模拟时钟验证的是调度规则、恢复和资源释放，不能冒充真实运行八小时或真实低配机器。
