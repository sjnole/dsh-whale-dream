# 鲸梦 0.8.35 · 启动屏、窗口配色与性能热修复

**日期：2026-11-16。基线：用户上传的 `dsh-whale-dream-0.8.34.tgz`（920 KB）。**

## 已核实的原因

1. 原包 `lib/startup/boot.js` 为 73,467 字节，即使当前只展示品牌文字，仍包含大段已经不用的鲸鱼数学、字符矩阵和画布形状数据；同一启动脚本也内联在大约 1.7 MB 的客户端 bundle 中。
2. `lib/startup/boot.js` 原动画最后段 `ANIMATION_END_MS` 为 **3,950ms**，另保留 1,000ms 和 360ms 的退场，代码级显示时长约 **5,310ms**。还使用逐字的模糊过渡及跨整窗光扫。
3. Windows 右上角按钮由 Electron 原生 `titleBarOverlay` 绘制：原版让 DSH 预加载色探针读取不透明的画布基色，而界面使用多层渐变，造成明显的方块色差。
4. `indexRows()` 根据 Host 开关取消注入时，老 `tapIndex()` 仍可能补注入启动脚本；浏览器本地开关也可能抢过 Host 配置。
5. 过白的 `HARNESS / Loading plugins…` 卡片属于 DSH 自带的框架无关 Boot UI；其 `[data-dsh-boot]` 读取 `--dsw-alias-bg-base`，可能被上游浅色预设覆盖。只有 Host 注入已经开始生效后的帧可由插件 CSS 调整。

## 实际修改

- `lib/startup/boot.js`：删掉当前不会使用的动画引擎旧代码，保留品牌图标与标题，动画仅使用 `opacity/transform`，取消模糊与全屏扫光。延时 **1,950ms**，退场 **220ms**，总计约 **2,170ms**，并有 3,000ms 异常保护。保留 Esc / 点击空白退出；不新增原来已删除的「跳过」按钮。
- `lib/client.js`：使用同一轻量启动代码替换客户端回退路径，继续保留其他编译逻辑；Windows 标题栏颜色探针改成透明背景，`::before` 拖动区仅透明化背景、不删除盒子或改动命中区域。
- `lib/startup/host.mjs`：无论启动开关开关都及早设置 DSH Boot UI 的底色；关闭时只下发小配置，不下发启动播放器；对 `tapIndex()` 加去重，Host 配置优先；读取 `whale-dream.json` 时按文件大小、修改与状态变更时间缓存配置，避免同次启动两个注入入口重复同步读取/解析大型壁纸配置。
- 插件原有的主题配色、动态外观、SJ 圆环、信息栏、账本和用户配置路径没有改动。

## 性能范围

| 项目 | 0.8.34 | 0.8.35 | 性质 |
|---|---:|---:|---|
| Host 启动脚本（字节） | 73,467 | 25,619 | 文件实测 |
| 客户端 bundle（字节） | 1,735,561 | 1,687,540 | 文件实测 |
| 默认品牌遮罩代码设定可见时长 | 5,310ms | 2,170ms | 代码时序计算，不是 DSH 冷启动耗时 |
| Canvas 动画计算 | 当前仅品牌幕布，不使用 | 同样不使用 | 检查执行路径 |

**注意**：只是缩短品牌幕布，不等同于加速 DSH 自身的模型初始化、插件下载或 Electron 冷启动。相同 DSH EXE 上的 CPU/GPU/RAM 前后量测尚未进行。


### 定向配置读取基准（非真实 DSH 启动）

本机 Node 环境以 **2.4 MB 合成壁纸配置**重复执行 `readStartupBoot()` 40 次，4 组交替测得组中位耗时：原版约 **124.0ms/40 次**，新版约 **0.206ms/40 次**。这一结果仅说明相同 JSON 不再重复读取/解析，属于**合成缓存微基准**，不代表 DSH 首屏耗时或整机性能有同等比例提升。配置文件变化后缓存已在专项测试中验证会失效并重新读取。

## 已执行的验证

- `node --check`：全部分发的 JS/MJS 文件语法检查通过。
- `docs/qa/smoke-0.8.35.mjs`：13 项专项测试全部通过，含 Host 禁用、重复注入、渐变与宿主配置优先、账户代码保留及标题栏探针。
- Chromium CDP 使用真实 Host 注入生成的 HTML：深色启动、浅色启动、计时自动清理、Esc 退出、禁用后不注入、透明 CSS 探针结果均通过。
- 对编译后的 `lib/client.js` 做归一化比较：去掉替换的启动 IIFE 与两组 WCO 配色声明后，其余内容与上传的 0.8.34 **逐字节一致**。

## 不可过度声称的验证

1. 上传的 0.8.34 TGZ **只有 `lib/` 编译产物，没有 `src/`、`build.mjs`、`tests/`、node_modules**，所以本轮是分发产物热补丁，不能运行旧项目的完整 TypeScript 构建及全部 38 种外观/信息栏回归测试。`npm run check` 在该包中不可用。后续回到全源码重构时必须同步移植上述改动。
2. 实际 Windows DSH 的 `setTitleBarOverlay({color:rgba(0,0,0,0)})` 能否在你的 Electron/显卡/系统组合下与渐变完全融合，**尚未实机验证**。透明原生叠加色的技术能力已通过 Electron 文档及本项目 DSH preload 源码核对；Chromium 测试只证明 CSS 探针输出透明。
3. DSH 原生 Boot 页若在 Host 注入之前已绘制白色帧，第三方插件无法提前控制 Electron/app.asar 的本机首帧；需修改 DSH 桌面外壳自身的启动背景作为根治，不能宣称本插件完全修复。
4. 暂未做多台不同配置电脑的真实 FPS、CPU 和内存压力测试，也不能把 Chromium 浏览器测试视作 Windows DSH 实机测试。

## 升级与回滚

按 DSH 插件管理流程，保留 `~/.dsh/whale-dream.json` 与 `~/.dsh/whale-dream-info/`；卸载旧版同名插件后，安装 `dsh-whale-dream-0.8.35.tgz`，完整从系统托盘退出后重开。若 Windows 原生叠加透明度不兼容，可回滚原 0.8.34 TGZ，不需要删除设置或账本。
